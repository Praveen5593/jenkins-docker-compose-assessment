# Jenkins CI/CD Pipeline with Docker Compose Deployment

## Objective
This assessment demonstrates Git integration, application build/testing, Docker image creation, Trivy security scanning, environment configuration, Docker Compose deployment, health checks, persistent database storage, image cleanup, and rollback.

## Project Structure
- `Jenkinsfile`
- `docker-compose.yml`
- `.env.example`
- `app/Dockerfile`
- `app/package.json`
- `app/server.js`
- `app/test.js`
- `reports/trivy-report.txt` (generated by Jenkins)

## CI/CD Workflow
1. Developer pushes code to Git.
2. Jenkins checks out the repository.
3. Jenkins installs Node.js dependencies and runs tests.
4. Jenkins builds `employee-app:<BUILD_NUMBER>`.
5. Trivy creates a HIGH/CRITICAL vulnerability report and applies a security gate.
6. Jenkins updates `APP_IMAGE` in the server-side `.env`.
7. Docker Compose deploys the Node.js app and MariaDB database.
8. MariaDB must become healthy before the app starts.
9. Jenkins calls `GET /health`.
10. On success, Jenkins records the image as the last successful image.
11. Jenkins removes dangling images and unused builder cache.
12. On deployment failure, Jenkins attempts to restore the previous successful image.

## Environment Setup
Copy `.env.example` to `.env` on the Jenkins/deployment server:

```bash
cp .env.example .env
```

Replace the example passwords with strong values. Never commit `.env`.

## Manual Commands
```bash
cd app
npm install
npm test
cd ..
docker build -t employee-app:manual ./app
```

Set:
```text
APP_IMAGE=employee-app:manual
```

Then:
```bash
docker compose --env-file .env up -d
docker compose --env-file .env ps
curl http://localhost:3001/health
curl http://localhost:3001/employees
```

Expected health response:
```json
{"status":"healthy"}
```

## Persistent Storage
MariaDB uses the named volume:

```text
employee_db_data
```

mounted at:

```text
/var/lib/mysql
```

This keeps database records even when containers are recreated.

## Trivy
The Jenkins pipeline generates:

```text
reports/trivy-report.txt
```

The security gate fails the build when actionable HIGH or CRITICAL vulnerabilities are detected.

## Rollback
Before a new deployment, Jenkins keeps the previously successful image tag. If the new deployment or health verification fails, the pipeline changes `APP_IMAGE` back to the previous image and runs Docker Compose again.

## Brief Explanation for Submission
The pipeline automates delivery from source code to a verified Docker Compose deployment. Jenkins checks out the Git repository, installs dependencies, runs tests, and builds a uniquely versioned Docker image. Trivy scans the image before deployment and acts as a security quality gate. Environment-specific values and secrets are kept outside Git in `.env`.

Docker Compose deploys the application and MariaDB on an isolated Docker network. MariaDB uses a named volume for persistent storage. Both services include health checks, and Jenkins performs an additional HTTP health verification after deployment. After a successful release, Jenkins records the image version and removes unused Docker build data. If a later deployment fails, the pipeline attempts to restore the previously successful image, demonstrating a simple automated rollback mechanism.
